# 内容怎么加

页面本身不再存内容。文章和照片都放在这个目录里，一处一篇，然后跑一次 `python build.py`，
它会生成 `data/posts.js` 与 `data/photos.js`，页面读这两个文件。

## 加一篇文章

在 `content/posts/` 新建一个文件，名字是 `编号-日期-标题.md`：

```
0002-2026-11-12-随便什么标题.md
```

里面这样写：

```markdown
---
date: 2026-11-12
cat: 生活
tags: 生活, 技术
title: 标题
desc: 卡片上那句摘要
---

第一段。

第二段。
```

- 文件名开头那四位是**编号**，定了就别改：卡片上的 NO.、地址栏的 `#post-02`、上下篇都认它。新文章往后排，跳号也没关系。
- `cat` 只能是这几个之一：摄像 / 软件 / 设计 / 技术 / 生活 / 阅读。它决定卡片颜色和统计里的分组。
- 空行分段。段内换行时，中文直接接上，英文之间补一个空格。
- 字段缺一个都不行。`build.py` 会逐个查，缺什么当场列出来，一个文件都不写，不会给你生成一个坏页面。

## 加一张照片

原图放 `content/originals/`（这个目录不进仓库），导出网页用的尺寸放到 `media/photos/`，
再在 `content/photos/` 新建一个 md：

```markdown
---
file: media/photos/photo-xxx.jpg
title: 标题
date: 2026.11.12
wide: true
alt: 一句话描述画面，读屏的人靠它看见这张照片
specs: 105mm|毫米, f/5.6|光圈, 1/500|快门, 640|ISO, D7100|机身
---

一句说明，会显示在卡片上。
```

- `wide: true` 用宽框（2.2:1），不写就是 3:2。两张一组时一宽一窄正好齐平。
- 不写 `specs` 就自动显示图片本身的尺寸，比如 `1440 × 655 像素`。
- 宽高由脚本自己读文件头，不用手填。
- 照片按文件名排序，卡片的 FRAME 编号跟着走。

## 然后

```
python build.py
```

终端会列出这次编进去的每一篇、每一张照片，以及总字数和文件大小。
把 `data/` 一起提交即可，Cloudflare Pages 那边不需要配构建命令。

页面真正读的是 `data/` 里那两个文件。写完不跑这一步就直接提交，线上会继续显示上一版内容 —— 这是这套结构唯一会咬人的地方。
